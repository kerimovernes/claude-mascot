# Проверка 0.3.1 — 06.11.2026

Исправлена обработка ввода при ручном перетаскивании ЛКМ: один проход обрабатывает
не более 256 сообщений Windows; соседние движения объединяются, а Down/Up и
команды сохраняют порядок. Повторный ShowWindow при прежней видимости пропускается.
Deadline кадра проверяется после обработки ввода. В `--trace` добавлены число
кадров, длительность drag и максимальный интервал кадров во время drag.

- Windows GNU, Rust 1.99.1: fmt, Clippy `-D warnings`, release build прошли.
- 84 теста: 39 library, 1 binary, 43 engine, 1 native lifecycle.
- Тест 100 000 движений проверяет объединение и сохранение барьеров событий.
- Win32-тест публикует 512 сообщений в приватную очередь потока и проверяет,
  что один pump возвращается до её полного опустошения. Реальный курсор не меняется.
- В QA-сеансе зафиксированы 484 кадра за 4,0341777 с перетаскивания: около
  119,98 FPS при выбранных 120; максимальный интервал 9,50 мс.
- Пользователь подтвердил: «теперь при перетаскивании фпс норм».

Это подтверждение конкретного сценария, не обещание одинаковой производительности
для всех мышей и частот опроса. Автоматическая попытка GUI-drag инструментом
не сработала из-за привязки координат; цифры взяты из зарегистрированных событий
перетаскивания QA-сеанса, а не из этой неудачной попытки автоматизации.
Тестовый процесс завершён штатно, конфигурация была отдельной.

Общий план и отчёты: `planning/PLAN-RU.md`. Новые идеи анимаций и фраз отмечены
как предложения и не включены в runtime 0.3.1. Проверки MSI/обновления/mixed-DPI
из плана остаются отдельными задачами; статическая валидация не заменяет их.
