## План: 12 карточек

Приоритеты: P0 — только воспроизводимый инцидент с data loss/security/crash; P1 — release gate/подтверждённый дефект; P2 — расширение или улучшение без подтверждённого release blocker. Сейчас подтверждённого P0 инцидента нет.

### P1 — release gates и подтверждённые пробелы

1. **Windows desktop QA matrix.** Зависимость: текущий Windows build. Пройти 100/125/150%, mixed DPI, отрицательный origin, click-through, topmost/no-activate, fullscreen, перенос/закрытие окон и idle input. Acceptance: протокол по каждому сценарию, все release-blocking дефекты исправлены и повторно проверены. Matrix остаётся неполной (`rust/docs/verification-0.3.0.md:47`).
2. **Проверить settings recovery.** `rust/src/settings.rs:43-70` возвращает ошибку при повреждённом JSON/версии. Воспроизвести и определить ожидаемое UX; при подтверждённом crash/data-loss риска — backup повреждённого файла и запуск с defaults без молчаливого затирания. Acceptance: invalid JSON, неизвестная версия, read-only folder и recovery flow имеют тесты; пользовательский файл не теряется.
3. **Измерить native idle и энергозатраты.** Зависимость: QA машина/методика из карточки 1. Снять baseline CPU/wakeups на 10 мин idle и 10 мин активности; только после baseline согласовать budget и оптимизацию. Acceptance: повторяемые измерения, версии/настройки записаны, wake/input после idle не теряются. Не вводить произвольный порог до baseline.
4. **Испытать install/update lifecycle.** Зависимость: чистая Windows VM. Install, autostart on/off, upgrade, interrupted update, uninstall. Acceptance: нет orphan startup/process; обычный uninstall следует документированной политике settings; ошибки обновления диагностируются. Полный lifecycle ещё не выполнялся (`verification-0.3.0.md:47-49`).
5. **Разобрать только оставшиеся climb edge cases.** Зависимость: карточка 1. Сохранить уже работающие `try_explore_jump` и climb; добавить тесты обеих сторон, occlusion, движущегося/закрытого окна и headroom. Acceptance: каждый воспроизводимый случай имеет regression test; нет застревания более 3 секунд/прохода сквозь поверхность. Не переписывать работающие автономные window hops.
6. **Закончить Windows video peek.** Зависимость: карточки 1 и 3. Проверить WinRT session→window mapping при нескольких окнах, position behind window и clipping. Acceptance: play включает только подтверждённое видео, pause выключает, audio-only не включает, закрытие target безопасно отсоединяет; чужое окно не меняется.

### P2 — продуктовые улучшения и решения

7. **Accessibility review и выбранные fixes.** Проверить keyboard traversal для pet/tray menus, focus, screen reader names, scaling/high contrast; решить reduced-motion. Acceptance: checklist для основных команд пройден клавиатурой/assistive tech и документированы Windows ограничения; fixes отдельно проходят checklist.
8. **Multi-pet manual/regression scenarios.** Проверить 8 экземпляров, per-entry menu targeting, spawn/remove, Tagilla/Claude interactions и длительную симуляцию. Acceptance: команда затрагивает питомца, чьё меню вызвано; удаление не трогает соседей; нет NaN/залипания. Friend menu уже есть.
9. **Решить, нужна ли сохранность roster.** Сегодня skin переключается для live pet, а settings/Python saved skin задают глобальный default. Это потенциальная новая возможность, не parity gap. Acceptance: зафиксирован выбор сохранить только default либо добавить persistent roster; при выборе roster — stable IDs, schema migration и тесты skin/removal/restart.
10. **Rust Linux host: отдельный vertical prototype KDE.** Зависимость: отдельная оценка бюджета, Windows не блокировать. Этапы: host abstraction, запуск/выход, KWin D-Bus snapshots, MPRIS, затем input/idle и opt-in `/dev/uinput`, Linux installer. Acceptance этапов — проверка на названной Plasma версии и graceful fallback без D-Bus/uinput; не обещать GNOME/all Wayland до проверки API.
11. **Проверить parity текущих общих действий и cancellation.** Dance/Wave уже реализованы в Rust 0.3.0 и являются additions; не добавлять их повторно. Проверить клики, отмену/замену временной команды, return-to-wander, меню mascot/tray и фидбек. Acceptance: тест переходов для каждой поддерживаемой команды и ручная проверка cancel/restore поведения.
12. **Visual parity backlog по сравнению одинаковых состояний.** Mood meter/satisfaction — Rust additions. Сравнить только общие позы/эффекты Python и Rust; заводить отдельные заметные расхождения (например, Tagilla cracks) с конкретными эталонами. Acceptance: side-by-side previews общих состояний и review; не требовать пиксельной идентичности без продуктового решения.

### P0

Подтверждённых P0 инцидентов сейчас не выявлено. Приоритет присваивается только после воспроизведения crash, data loss или security issue с доказательством и owner.

## Границы статуса

Самостоятельные прыжки на окна уже реализованы и покрыты regression cases. Live skin меняется per-pet; persistence остаётся глобальным default, как у Python. Satisfaction, mood meter, dance и wave — новые Rust функции. Windows menu осматривали вручную; полноценная accessibility QA отдельно не выполнена. Linux интеграции — отдельный host scope.
