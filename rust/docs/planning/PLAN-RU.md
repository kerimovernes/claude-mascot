# План развития и проверки Claude Mascot Rust

Актуализация 0.6.0: семь парных сцен, включая догонялки и башенку из двух
питомцев с физическим прыжком и спрыгиванием; реакции на Explorer и короткая
игра с курсором; адаптивные высокие прыжки и best-effort опоры на значках
рабочего стола через публичную UIA. Усилены движения глаз, анимация «дай пять»
и общий ноутбук. Посторонний человек из сцены программирования удалён.
Проверки: [verification-0.6.0.md](../verification-0.6.0.md).

Актуализация 0.5.0: перенесены все 75 иллюстраций пользовательского пака в
косметические занятия с таймлайном и репликами, добавлены пять дружеских
парных сцен, взгляд за близким курсором и задняя крышка ноутбука.
По уточнению пользователя исходные тела/лица из пака не подменяют питомца:
у всех занятий один канонический Claude, меняются его позы и предметы.
В меню есть полный каталог и переключатели случайных занятий/взаимодействий.
Исходный банк из 40 предложенных фраз остаётся отдельным файлом; 75 реплик
занятий и реплики парных сцен уже используются в runtime.
Проверки текущей версии: [verification-0.5.0.md](../verification-0.5.0.md).
Старые таблицы ниже сохраняют исторический статус аудита 0.3.x.

Актуализация 0.4.0: Rust теперь содержит только Claude. Удалены смена персонажа,
боевые состояния, эффекты и загрузка атласа. Реализованы ноутбук (1+8+1 с),
потягивание (2,5 с), осмотр (2 с), команды меню и редкие idle-запуски.
Банк из 40 фраз остаётся предложением. Ниже сохранён аудит базы 0.3.x;
упоминания второго персонажа и missing atlas больше не задают текущий scope.
Текущие проверки: [verification-0.4.0.md](../verification-0.4.0.md).

Дата: 06.11.2026. База: 0.3.0, ветка `rust-rewrite`.
Этот документ отделяет реализованные возможности от предложений и непроверенных
сценариев. Зелёные unit-тесты не означают, что установщик и обновление проверены
на реальной установленной копии.

## Распределение текущего прохода

| Владелец | Область | Состояние | Результат и условие приёмки |
| --- | --- | --- | --- |
| product_roadmap_low, Luna low | Оригинал Python/Linux, возможности и пользовательские сценарии | Аудит завершён | [Матрица паритета](product-parity.md), исправлены устаревшие сведения о 0.3.0 |
| runtime_audit_low, Luna low | Физика, состояния, графика, окна, ресурсы | Аудит и исправление завершены | [Runtime-аудит](runtime-audit.md), регрессии очереди и видимости прошли |
| release_audit_low, Luna low | MSI, portable, обновления, безопасность, CI | Аудит завершён | [Аудит поставки](release-audit.md), новых подтверждённых дефектов не найдено |
| Основной агент | Интеграция, настройки, единый план и проверка результатов | Проверено | Свежий deadline после ввода, метрики drag, 84 теста и подтверждение пользователя |

Агенты не публикуют релизы, не устанавливают/удаляют пользовательскую копию и
не меняют Defender. Исправления ограничены подтверждёнными дефектами; крупные
функции сначала получают отдельный этап и критерии готовности.

## Архитектурные границы

- `engine.rs`: поведение и физика по снимку мира; никаких команд чужим окнам
  или реальному курсору. Одинаковые входные данные должны давать повторяемый результат.
- `platform.rs`: Win32, мониторы, DPI, ввод, hit-test, трей и нативное меню;
  собственные ресурсы освобождаются при частичном отказе и завершении.
- `render.rs`: кадр и анимации; сглаженный текст рисуется в конечном разрешении,
  пиксельный персонаж сохраняет свой стиль. Настроение и поза не определяют физику.
- `main.rs`: жизненный цикл приложения и связь команд с движком. Из него имеет
  смысл выделять контроллеры только при конкретной пользе для тестирования.
- `settings.rs`: валидация, миграция, атомарная запись и безопасное восстановление.
- `media.rs`: изолированный best-effort сбор медиа-состояния без блокировки GUI.
- `update*.rs`: проверка источника и целостности, согласие на загрузку/перезапуск,
  замена с откатом; файлы MSI принадлежат Windows Installer.

## Очерёдность

### Единая доска задач

P0 — подтверждённая потеря данных, уязвимость или аварийный отказ; сейчас таких
инцидентов не выявлено. P1 — дефект либо проверка, необходимая перед широким
выпуском. P2 — последующее улучшение. Приоритеты этой таблицы имеют преимущество
над локальными пометками в отдельных отчётах. Владельцы назначены по областям;
«готова к работе» не означает, что агент продолжает её выполнять после аудита.

| ID | Приоритет, состояние | Владелец | Конкретный результат / приёмка |
| --- | --- | --- | --- |
| F01 | P1, закрыта для проверенного сценария | runtime_audit_low + интегратор | Pump ограничен, moves объединяются, ShowWindow только при смене видимости; 484 кадра за 4,034 с drag при 120 FPS, пользователь подтвердил исправление |
| F02 | P1, нужна изолированная Windows-среда | release_audit_low | MSI clean install → upgrade → uninstall; работающий EXE, автозапуск и настройки сохраняются/очищаются по контракту |
| F03 | P1, нужен fixture и подходящий release asset | release_audit_low | Полный update/rollback с digest, offline, занятым файлом, запуском; согласованный тестовый канал либо существующий подходящий релиз |
| F04 | P1, готова к проектированию | интегратор, settings/main | Recovery повреждённого JSON и missing atlas; сохранить исходные данные; неизвестную будущую схему не перезаписывать defaults |
| F05 | P1, нужна матрица оборудования | runtime_audit_low | 100/125/150/200%, mixed DPI, отрицательный origin, отключение монитора; отдельные фактические результаты |
| F06 | P1, готова к работе | runtime_audit_low | Capture/cancel/двойной клик/переключение приложений; ровно одно завершение drag, без зависшего capture |
| F07 | P1, готова к измерениям | runtime_audit_low | CPU/память/handles 1/4/8 питомцев, idle и active; выбрать бюджет после базового замера |
| F08 | P1, готова к работе | интегратор, settings/main | Автозапуск и второй экземпляр: различать свою запись Run и другую копию; повторный запуск сообщает о работающей версии, не исчезает молча |
| F09 | P2, готова к спецификации | product_roadmap_low + runtime | Отмена/замена команд, более сложные маршруты по окнам и медиа-подглядывание; сценарий начала/прерывания/завершения для каждого действия |
| F10 | P2, готова к проверке | product_roadmap_low + native UI | Клавиатура, контраст, меньше движений, восстановление питомца на экране; команды доступны и понятны |
| F11 | P2, требуется продуктовое решение | product_roadmap_low + settings | Сохранять ли roster/настроение между сеансами; при выборе — стабильные IDs, миграция, правила удаления и приватности |
| F12 | P2, исследование отдельно | product_roadmap_low + новый platform-owner | Rust Linux vertical prototype на конкретной системе; контракты backend и проверка возможностей до обещаний паритета |
| F13 | P2, каталог и фразы подготовлены, реализация отдельно | product_roadmap_low + renderer-owner | Ноутбук: достал → открыл → печатает → закрыл; затем остальные новые сцены и банк фраз с cooldown/anti-repeat, без наблюдения за клавиатурой и реального ввода |

Для F04/F08 подтверждены текущие ограничения исходников: `main.rs::native::run`
молча завершает второй экземпляр и распространяет ошибки settings/atlas через
`?`; `settings.rs::autostart_enabled` проверяет наличие значения Run, а не путь.
Это отдельные задачи, а не утверждение, что соответствующие улучшения уже внесены.

При новой ошибке обновляется карточка и её доказательства, а не добавляется
ещё одна бесконечная очередь функций. F01 появился после сообщения пользователя
о просадке FPS и сразу стал текущей работой.

### Этап A. Стабильная Windows-бета

1. Разобрать подтверждённые дефекты из трёх аудитов. Любое исправление получает
   сценарий воспроизведения и регрессионную проверку, где она полезна.
2. Проверить установленный MSI в изолированной Windows-среде: чистая установка,
   обновление с предыдущей версией, работающий EXE, удаление, сохранение настроек,
   очистка своего автозапуска, отсутствие повреждения другой копии.
3. Проверить полный portable update: релиз → загрузка → digest → согласие →
   завершение процесса → замена → перезапуск; отдельно сеть без доступа, неверный
   digest, занятый файл и откат. Не использовать опубликованный тестовый EXE без
   заранее определённого тестового канала.
4. Закрыть восстановление настроек и старт: повреждённый JSON, неподдерживаемая
   версия, недоступная папка, пропавший custom atlas, повторный запуск приложения.
5. Пройти ручную матрицу Windows/DPI/мониторов/полноэкранных приложений и измерить
   CPU/память для 1, 4 и 8 питомцев при 60/120/240 FPS. Порог нагрузки назначать
   по измеренной базовой линии, не обещать универсальные числа заранее.

Готовность этапа: воспроизводимые P0/P1 закрыты либо явно удерживают выпуск;
проверки установки и обновления имеют протокол среды и фактический результат.
Окончательный вердикт Microsoft по старому образцу проверяется отдельно и не
выводится из отсутствия локального срабатывания новой сборки.

### Этап B. Удобство ежедневного использования

- Понятные режимы: спокойный, активный, не беспокоить; действия, которые
  приостанавливают автономность, должны иметь предсказуемую отмену.
- Доступные команды для восстановления питомца на экране, управления всеми
  друзьями и отображения версии. Повторный запуск не должен выглядеть как отказ.
- Настройки частоты действий, прыжков и реакций; отдельные параметры только там,
  где они решают реальную потребность, без десятков лишних переключателей.
- Настроение: согласованные реакции, отсутствие наказания за обычное перемещение,
  понятная шкала. Сохранение между сеансами — отдельное решение и переключатель;
  сейчас настроение временное.
- Доступность: читаемый текст, управление с клавиатуры, отключение эффектов и
  уменьшение движений; проверить системный масштаб и контраст.

Готовность этапа: каждый пользовательский путь имеет видимый результат, состояние
настроек сохраняется, действия работают при паузе/сне/погоне без зависших состояний.

### Этап C. Более богатое поведение

- Переносить отсутствующие действия из оригинала по матрице `product-parity.md`.
  Для каждого действия определить запуск, прерывание, завершение и совместимость
  с погоней, сном, окнами и несколькими питомцами.
- Углубить маршруты по окнам, захват краёв, обход препятствий и совместные реакции.
- Доработать Тагиллу, медиа-реакции, реплики и дополнительные позы на основании
  оригинала. Сначала согласовать формат анимаций и данных, затем добавлять контент.
- Реальные воздействия на курсор/чужие окна не включать в обычный режим молча;
  это отдельное пользовательское решение, а не условие «полного» порта.

Готовность этапа: поведение проверяется сценариями, а не только количеством новых
состояний; поддерживается стабильная частота физики и ограниченный бюджет эффектов.

### Этап D. Другие платформы и поддержка

- Rust Linux host — самостоятельный проектный этап. Исследовать целевые окружения,
  доступные API и ограничения; общий Python-код не доказывает наличие Rust backend.
- Выделить контракт платформы после определения второго реального backend,
  сохранить тестируемый общий движок и сравнить поведение на целевых системах.
- Версионируемые пакеты скинов/анимаций, документация для автора контента,
  локальные диагностические сведения без автоматической отправки личных данных.
- Каналы выпусков, подпись кода, правила совместимости и поддержка старых настроек.

## Правило выпуска

Сначала конкретные изменения и проверки, затем версия и артефакты, затем
публикация в согласованный канал. План не означает, что все этапы уже реализованы.
Проверки кода, настоящей Windows-среды и внешнего сервиса фиксируются отдельно.
