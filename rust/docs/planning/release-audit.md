# Аудит выпуска Rust 0.3.0

Дата: 2026-11-06
Область: встроенный обновлятор, portable-инсталляция, MSI и GitHub Actions.

## Результат

В проверенных путях не обнаружен подтверждённый дефект, который оправдывает изменение кода в этом аудите. Текущий updater принимает только стабильные версии новее установленной, сверяет имя и канонический URL asset, ограничивает размер, проверяет digest и PE x64, а замену выполняет отдельный helper после выхода приложения. Helper сохраняет предыдущий exe, проверяет запуск новой версии и пытается откатить замену при ошибке. MSI-установка помечается отдельным файлом и исключена из встроенного обновления. Скрипты portable-удаления ограничивают удаление собственным каталогом и сохраняют настройки по умолчанию.

В рамках аудита не запускались установщик, удаление, release-сборка, проверка антивирусом и публикация артефактов. Не менялись корневые legacy-файлы. Существующие изменения `install.bat`, `uninstall.bat` и `uninstall.ps1` оставлены без изменений.

## Подтверждённые свойства

- `rust/src/update.rs`: выбирается только более новая стабильная версия; принимается ожидаемый x64 asset, единственный digest SHA-256 и точный URL GitHub Releases.
- `rust/src/update_http.rs`: загрузка ограничена по времени и размеру, используется системная проверка TLS, запрещён переход HTTPS→HTTP; проверяются размер, digest и заголовок MZ.
- `rust/src/update_apply.rs`: helper проверяет PE x64, пути staging, PID и образ родительского процесса; MSI-owned каталог отклоняется; копирование и переименование не перезаписывают существующие файлы; при неудачном запуске предусмотрен откат.
- `rust/Install.ps1`, `rust/Uninstall.ps1`, `rust/installer/Package.wxs`: portable и MSI защищены от взаимного управления через marker; portable-удаление сопоставляет процессы/ярлыки и сохраняет файлы настроек, если не задан `-RemoveSettings`.
- `.github/workflows/rust-release.yml`: сборка проверяет соответствие версии Cargo тегу, выполняет fmt/tests/clippy, собирает x64 exe и MSI, формирует SHA256SUMS и публикует только артефакты прошедшей сборки.

## Backlog

### P2: проверить поведение WinHTTP перенаправлений на реальном GitHub CDN

**Основание:** транспорт явно допускает безопасные HTTPS перенаправления, а загрузка GitHub Release обычно переходит на CDN. В коде нет отдельного теста, запускающего WinHTTP против реального маршрута. Это оставлено как проверка совместимости, не как подтверждённый дефект.

**Критерии приёмки:** на чистой Windows 10 и Windows 11 x64 выполнить ручную проверку обновления с подтверждением пользователя; подтвердить успешный HTTPS redirect до CDN, ограничение на HTTPS, совпадение размера/digest и запуск staged-версии. Зафиксировать ОС, версии, HTTP-результат и SHA-256. Не публиковать новый релиз для этой проверки.

### P2: проверить MSI upgrade/remove на Windows без установки пользователем

**Основание:** декларативная схема WiX включает MajorUpgrade, marker владения и deferred custom action для удаления собственной записи автозапуска. Статическое чтение не доказывает реальное поведение Windows Installer при обновлении и удалении.

**Критерии приёмки:** в одноразовой VM установить MSI, включить автозапуск, обновить MSI на следующую тестовую версию и удалить его; подтвердить отсутствие собственной записи Run после полного удаления, корректную замену exe, отсутствие удаления пользовательских настроек и невозможность portable updater управлять MSI-каталогом. Проверку проводить без реальной пользовательской установки и без публикации артефактов.

## Не закрытые runtime-проверки и ограничения

- Не проверялась установка/обновление/удаление MSI в Windows VM и не проверялся ручной updater end-to-end.
- Не проверялась воспроизводимость двух независимых release-сборок; workflow обеспечивает locked-зависимости и хэш-манифест, но не заявляет битовую воспроизводимость.
- Встроенный updater проверяет SHA-256 из GitHub release metadata, но не проверяет Authenticode-подпись издателя. Digest подтверждает целостность относительно метаданных GitHub, но сам по себе не является независимой подписью издателя.
- Предыдущие exe сохраняются рядом с приложением после успешного обновления; автоматической политики очистки резервных копий не обнаружено. Это сохраняет путь ручного восстановления, но может накапливать файлы.
- По историческому контексту исходный 0.1.0 EXE вызвал Microsoft Defender `Trojan:Script/Wacatac.C!ml`; образец был отправлен Microsoft, окончательный вердикт в этом проходе не проверялся, а локальная чистая проверка 0.3.0 не доказывает статус на других системах. В рамках этого аудита образец не отправлялся, настройки Defender не менялись, исключения не добавлялись.
