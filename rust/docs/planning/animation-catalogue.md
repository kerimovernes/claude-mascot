# Предложения новых анимаций и действий

Обновление 0.4.0: реализованы ноутбук (1 с открыть, 8 с печатать, 1 с закрыть),
потягивание (2,5 с) и осмотр (2 с) как команды и редкие idle-действия.
Потягивание после сна, дополнительные cooldown/mood-условия и остальные сцены
ниже остаются предложениями. `Dance` и `Wave` уже существовали.
Питомец декоративный: не читает клавиатурный ввод, не открывает приложения,
не меняет файлы и не использует сеть для анимаций.

Для идеи laptop-анимации существуют внешние визуальные примеры: [Clawd Buddy README / typing GIF](https://github.com/zhanbodev/clawd-buddy/tree/dev) и [Clawd asset `clawd-typing.gif`](https://github.com/KebeliSamet0/clawd/tree/master/assets/gif). Это ссылки для референса, не разрешение на включение чужого artwork. В Rust предпочтителен собственный CPU-rendered pixel prop в стиле текущего питомца и последовательность LaptopOpen → Typing → LaptopClose; не копировать GIF/кадры в assets без отдельной лицензии и проверки атрибуции.

## Общие правила действия

- Каждая новая последовательность должна быть детерминированным состоянием/таймлайном с ограниченной длительностью, а не отдельным бесконечным loop.
- Приоритет прерывания: падение/столкновение с реальной физикой, пользовательское перетаскивание, явная команда/смена кожи, затем обычный idle. Прерванное действие безопасно сбрасывает временные props и возвращается в валидное состояние питомца.
- Автономные действия допускаются только в поддерживаемом состоянии (на поверхности, не перетаскивается, не спит/сидит по явной команде); не блокируют управление и не меняют satisfaction от случайного прерывания.
- Расширить renderer preview и regression coverage для начала, середины, конца и прерывания каждого действия до включения в меню или idle-планировщик.

## Проверяемые требования перед реализацией

1. У каждой анимации есть preview ключевых кадров и тесты тайминга/возврата в locomotion.
2. Для laptop chain отдельные тесты прерывания на каждом этапе (достал, печатает, закрывает): drag/fall/command удаляют prop сразу и никогда не оставляют его на экране.
3. Сценарии с краями не меняют физическую позицию и не обходят проверки опоры; физика имеет приоритет над декоративной позой.
4. Cooldown и random choice используют стабильный RNG питомца; один питомец не запускает idle-action чаще заданного лимита.
5. Новые пункты меню добавляются только после проверки, что они доступны и клавиатурой; случайные idle-анимации не должны требовать открытия меню.
