# Windows host notes

`platform::initialize()` must run before creating any HWND. It opts the process into per-monitor-v2 DPI awareness so simulation coordinates, monitor bounds, cursor positions, and layered-window placement all use physical pixels in the virtual desktop coordinate space. Negative coordinates are preserved for monitors placed to the left or above the primary display.

`InstanceGuard::acquire(name)` owns a named Windows mutex handle for the life of the returned guard. It returns `Ok(None)` when a named mutex already exists and propagates other Win32 errors. The application chooses the stable mutex name and decides how to report the already-running case.

Each `NativeHost` owns one frameless `WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` popup. Call `set_size(width, height)` before presenting when the character scale changes. The `present` pixel slice is a row-major, premultiplied BGRA surface encoded as `u32` ARGB values on little-endian Windows. Transparent pixels are hit-test transparent; opaque character pixels receive mouse input. Pointer events carry physical desktop coordinates. The HWND is held in a stable boxed state block passed as `GWLP_USERDATA`; the window callback only appends events behind a mutex, avoiding aliased mutable access to the Rust host.

The standard menu and optional notification icon post the command IDs declared by the application contract. Only hosts constructed with `tray = true` add an icon. Call `set_menu_state(MenuState { .. })` when app state changes to show native checkmarks for the selected action, skin, pause/fullscreen/autostart options, rage/chase states, and current scale. Close requests become `InputEvent::Quit`; the owner is responsible for applying its lifecycle policy and dropping hosts. `NativeHost::pump()` drains messages for every HWND on the UI thread, and `wait()` blocks for messages with a timeout.

`snapshot()` returns visible, non-minimized foreign top-level windows bottom-to-top, extended-frame bounds from DWM when available, monitor work areas, foreground/fullscreen state, cursor position, and last-input idle time. It excludes this process, owned windows, tool windows, known shell desktop/taskbar classes, and DWM-cloaked windows. `video_window` stays `None` in the snapshot itself. The optional `MediaMonitor` polls Windows Global System Media Transport Controls every 1.5 seconds on a worker thread, accepts only sessions marked both `Playing` and `Video`, then maps the source app ID to a visible window by querying its process executable. Firefox package/app IDs normalize to `firefox`; audio-only sessions and unknown playback types are ignored. No title-based playback inference is used. The worker owns a WinRT multithreaded apartment and is signalled on drop; its join handle detaches so an unresponsive Windows media service cannot block app shutdown.

Display changes are reflected by the next snapshot poll. Applications should call `snapshot()` after `WM_DISPLAYCHANGE` or as part of their regular world update. Current fullscreen detection compares the active window's extended-frame rectangle with a monitor rectangle (within two pixels), which covers ordinary exclusive and borderless single-monitor fullscreen windows. Multi-monitor spanning apps may need a policy that checks coverage of all monitors.
